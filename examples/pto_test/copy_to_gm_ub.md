## AscendC 中的其他 Copy 方法

基于 `src/tl_templates/ascend/common.h`，还有以下 copy 方法：

### 1. `copy_gm_to_ub` (已讲过)
```cpp
GM → UB
```

### 2. `copy_ub_to_gm` (已讲过)
```cpp
UB → GM
```

### 3. `copy_ub_to_ub`
```cpp
template <typename T1, typename T2, uint32_t len>
CATLASS_DEVICE void copy_ub_to_ub(LocalTensor<T1> dstTensor,
                                  LocalTensor<T2> srcTensor);
```
**用途**：UB 内部复制，支持类型转换（如 float ↔ half）

### 4. `copy_ub_to_l1`
```cpp
template <typename T, uint32_t M, uint32_t N>
CATLASS_DEVICE void copy_ub_to_l1(LocalTensor<T> dstTensor,
                                  LocalTensor<T> srcTensor);
```
**用途**：UB → L1 Buffer，只支持 half 类型，用于 ND→NZ 格式转换

## 完整的数据移动 API 体系

```
                │   Global    │
                │  Memory     │
                └──────┬──────┘
                       │
         ┌─────────────┼─────────────┐
         │             │             │
    GM→UB         UB→GM         UB→UB
    (加载)        (写回)       (内部复制)
         │             │

         │                           │

    ┌─────────┐              ┌──────────┐
    │   UB    │─────────────►│   L1     │
    └─────────┘   UB→L1      └──────────┘
```

  内部执行逻辑

  // 1. 创建 GlobalTensor 描述
  pto::GlobalTensor<float,
      pto::Shape<1, 1, 1, 1, 1024, 1>,
      pto::Stride<524288, 262144, 16384, 1, 1, 1>
  > global_tensor(S_handle + gm_offset);

  // 2. 计算 UB 地址
  // ub_addr = 0 + 0 * 4 = 0
  TileUbDataND<float, 1, 1024, 1, 1024> temp_ub;
  pto::TASSIGN(temp_ub, 0);

  // 3. 执行存储：UB[0:4] → GM[offset:offset+4]
  pto::TSTORE(global_tensor, temp_ub);

  ⚠️ 问题分析

  这是一个有问题的调用！

  根据 PTO 的 copy_ub_to_gm 实现：

  pto::TASSIGN(temp_ub, ub_shape_addr + ub_offset * len);

  这里计算的是：
  - ub_addr = 0 + 0 * 4 = 0

  但 TSTORE 会存储 整个 temp_ub (1024 个 float) 到 GM，而不是只有 4 个元素！

  参数 len=4 只用于计算 UB 偏移，不控制复制长度。

  实际效果

  GM 目标地址 = S_handle + ((cid/16)*32768 + vid*16384 + (cid%16)*1024)

  实际复制：UB[0:1024] → GM[offset:offset+1024]

  应该如何修正

  如果只想复制 4 个元素：

  // 方案1：修改 valid 参数
  tl::ascend_pto::copy_ub_to_gm<float, float, 1, 1, 1, 1, 1024, 1,
      16384 * 16 * 2, 16384 * 16, 16384, 1, 1, 1024,
      1, 1024,      // ub_shape
      1, 4          // valid: 只复制 4 个有效元素
  >(S_handle + offset, 0, 0, 4);

  // 方案2：直接使用更小的 UB
  tl::ascend_pto::TileUbDataND<float, 1, 4, 1, 4> small_ub;
  TASSIGN(small_ub, 0);
  // ... 计算 4 个元素 ...
  pto::TSTORE(global_tensor, small_ub);

  如果想复制全部 1024 个元素（这可能才是本意）：

  tl::ascend_pto::copy_ub_to_gm<float, float, 1, 1, 1, 1, 1024, 1,
      16384 * 16 * 2, 16384 * 16, 16384, 1, 1, 1024,
      1, 1024,     // ub_shape
      1, 1024      // valid: 复制全部 1024 个
  >(S_handle + offset, 0, 0, 1024);  // len 应该是 1024

  总结

  当前调用的问题：
  - len=4 只影响偏移计算，不影响复制长度
  - 实际会复制 1024 个 float (4096 字节)
  - len=4 很可能是错误，应该是 len=1024

copy_gm_to_ub 方法详解

  函数签名

  template <typename T, uint32_t dstN, uint32_t dstM = 1>
  CATLASS_DEVICE void copy_gm_to_ub(
      LocalTensor<T> dstTensor,    // 目标 UB Tensor
      GlobalTensor<T> srcTensor,   // 源 GM Tensor
      uint32_t realSrcN = 1        // 实际源维度大小（用于 stride 计算）
  );

  数据流向： GM (全局内存) → UB (本地高速缓存)

  ---
  具体调用分析

  tl::ascend::copy_gm_to_ub<float, 1024>(
      g_ub[0],                                              // dstTensor
      G[((((cid / 16) * 32768) + (vid * 16384)) + ((cid % 16) * 1024))],  // srcTensor
      524288                                                // realSrcN

  GM 地址计算

  GM_offset = ((cid / 16) * 32768) + (vid * 16384) + ((cid % 16) * 1024)

  地址计算分解

  假设测试数据是 (B=2, H=16, L=16384)：
  ┌─────────────┬────────────────────────┬────────────────────────────────────────────────────────────────────────────────────────────┐
  │    组件     │          计算          │                                            说明                                            │
  ├─────────────┼────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ cid / 16    │ 0~31                   │ 块索引除以 16，得到组索引                                                                  │
  ├─────────────┼────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ * 32768     │ 32768 × 31 = 1,017,216 │ 每组包含 16 个块，每个块处理 1024 元素，两组处理 2048 元素（16×128），所以 32768 = 16×2048 │
  ├─────────────┼────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ vid * 16384 │ 0 或 16384             │ 子块索引（AIV 核心有两个向量引擎）                                                         │
  ├─────────────┼────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ cid % 16    │ 0~15                   │ 组内块索引                                                                                 │
  ├─────────────┼────────────────────────┼────────────────────────────────────────────────────────────────────────────────────────────┤
  │ * 1024      │ 0~15360                │ 块内偏移                                                                                   │
  └─────────────┴────────────────────────┴────────────────────────────────────────────────────────────────────────────────────────────┘
  数据布局示意

  GM 内存布局 (L=16384, 每块 1024):
  ┌─────────────────────────────────────────────────────┐
  │ Block 0  │ Block 1  │ ... │ Block 15 │  ← Group 0  │ (cid 0-15)
  ├─────────────────────────────────────────────────────┤
  │ Block 16 │ Block 17 │ ... │ Block 31 │  ← Group 1  │ (cid 16-31)
  ├─────────────────────────────────────────────────────┤
  │                      ...                            │
  └─────────────────────────────────────────────────────┘

  每个块处理 1024 个 float (4096 字节)

  内部实现解析

  AscendC::DataCopyExtParams dataCopyParams(
      1,                              // dstM = 1 (行数)
      1024 * sizeof(float),           // 每行大小 = 4096 字节
      (524288 - 1024) * sizeof(float), // 源 stride = 523264 × 4 = 2,093,056 字节
      0,                              // 目标 stride
      0                               // 填充模式
  );
  AscendC::DataCopyPad(dstTensor, srcTensor, dataCopyParams, padParams);

  Stride 含义

  realSrcN = 524288 表示：
  - 源 GM 中，连续两行数据之间的间隔是 524288 个 float 元素
  - 524288 = 512 × 1024，即 512 个块的大小
  - 这意味着从 GM 读取时，跳过了大量数据

  GM 中数据读取模式（只读 1024 个，但 stride 是 524288）:

  G[0]    ━━━━━━━━━━━━━━━━━━━━━━━━━━► 读取 1024 个元素
  G[1024] ━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
  G[2048] ━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
  ...     ━━━━━━━━━━━━━━━━━━━━━━━━━━━┓ 跳过 523264 个元素
  G[524288] ━━━━━━━━━━━━━━━━━━━━━━━━━━┛ (下一次读取位置，但实际不会读)

  ⚠️ 潜在问题分析

  问题 1：realSrcN 参数可能过大

  realSrcN = 524288  // 这是总数据量 (2×16×16384) / (2×16×128)

  对于单个块来说，realSrcN 应该是：
  - 如果只想读当前块：realSrcN = 1024
  - 如果需要跨块读取：根据实际跨块数计算

  当前设置 realSrcN = 524288 可能导致：
  - Stride 过大，访问超出预期范围
  - 如果 GM 中没有足够数据，可能读取未初始化内存

  问题 2：正确的参数应该是什么？

  根据测试数据 (B=2, H=16, L=16384) 和 chunk 大小 C=128：

  每个块处理的数据：8 chunks × 128 elements = 1024 元素
  总 chunk 数：16384 / (128×8) = 16 chunks (per block per H)

  如果只是简单复制：
  tl::ascend::copy_gm_to_ub<float, 1024>(g_ub[0], G[offset], 1024);

  ---
  总结

  本次调用实际效果

  从 GM[offset] 开始，复制 1024 个 float 到 g_ub[0]
  但告诉编译器源 GM 的 stride 是 524288

  数据流向图

  Global Memory (GM)                    Union Buffer (UB)
  ┌─────────────────┐                  ┌──────────────────┐
  │ G[offset]       │ ──────────────►  │ g_ub[0]          │
  │ G[offset+1]     │ ──────────────►  │ g_ub[1]          │
  │ ...             │ ──────────────►  │ ...              │
  │ G[offset+1023] │ ──────────────►  │ g_ub[1023]       │
  │ G[offset+1024] │ XXX (跳过)        │                  │
  │ ...             │ XXX (跳过大量)    │                  │
  └─────────────────┘                  └──────────────────┘
        ↑                                         ↑
     计算出的偏移                          只复制 1024 个

  建议

  如果只是复制连续的 1024 个元素，应该使用：

  tl::ascend::copy_gm_to_ub<float, 1024>(
      g_ub[0],
      G[((((cid / 16) * 32768) + (vid * 16384)) + ((cid % 16) * 1024))],
      1024  // 而不是 524288
  );
